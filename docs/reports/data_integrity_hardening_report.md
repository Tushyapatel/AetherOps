# AtherOps Demo Scenario Repair: Data-Integrity & Visual Truthfulness Hardening Report

## Overview
This report summarizes the corrections made to the AtherOps frontend and backend components to ensure visual truthfulness and data integrity in the generated demo environments. Our primary objective was to ensure the dashboard reflects authentic, deterministic data generated by the backend engines, rather than displaying hardcoded or fabricated information, avoiding any misrepresentation.

## Issues Identified & Addressed

### 1. Risk Trend "Invalid Date"
*   **Issue:** The Risk Trends section on the Project Overview page was rendering "Invalid Date" because the frontend was relying on a `created_at` field which wasn't available or was improperly serialized in the risk history objects.
*   **Resolution:** 
    *   Updated the `Dashboard.tsx` to read from the correct `recorded_at` field generated by the risk scoring backend.
    *   Implemented robust date parsing (`new Date(score.recorded_at).toLocaleDateString()`) to handle edge cases and prevent invalid date strings from rendering.

### 2. Blank Targets in Attack Paths
*   **Issue:** The Attack Paths page contained blank entries for "Target" because the demo seed scripts created `finding_chain` metadata as serialized structures, but the frontend was not parsing these chains properly to extract the target node.
*   **Resolution:** 
    *   Refactored `AttackPaths.tsx` to correctly implement `parseChain(path.finding_chain)` which handles both raw stringified JSON and pre-parsed array structures.
    *   Modified the UI to dynamically pluck the target from the last node of the array (`target = getTargetDisplay(chain)`) and the entry point from the first node.

### 3. Misleading "ACTUAL AWS BILLING" Label
*   **Issue:** The `Costs.tsx` component and the `ReportService` were unconditionally hardcoding the string `ACTUAL AWS BILLING`, despite the data actually being simulated for the demo environments.
*   **Resolution:** 
    *   Updated the backend `/dashboard` endpoint and `report.service.ts` to attach a `meta: { billing_source: 'SIMULATED_DEMO' }` context tag when injecting demo environments.
    *   Modified `Costs.tsx` and the report generation logic to dynamically switch labels between `SIMULATED DEMO BILLING` and `ACTUAL AWS BILLING` based on this new `billing_source` field, eliminating misleading claims in the dashboard.

### 4. Risk Engine Idempotency
*   **Issue:** Running the demo seed script multiple times led to bloated counts (e.g., hundreds of risk scores for a single environment) because it didn't clear older records before re-inserting.
*   **Resolution:** 
    *   Added idempotency checks in `demo_finalize.ts` to `DELETE FROM risk_scores` and `DELETE FROM risk_history` for the specific `project_id` before populating fresh engine data, ensuring data integrity remains clean across multiple seed runs.

### 5. Frontend Test Suite Failures
*   **Issue:** The addition of these rigorous checks resulted in the frontend `vitest` suite failing due to a `TypeError: projects.map is not a function`. The newly enforced `AppShell` component dependencies required a strict API array response.
*   **Resolution:** 
    *   Isolated the mock network requests in `App.test.tsx` by replacing indiscriminate mock hooks with `url === '/api/v1/projects'` checks. This prevents the navigation header components from crashing on arbitrary `{ data: {} }` endpoint payloads during isolated page tests.
    *   Adjusted Testing Library queries from `getByText` to `getAllByText(...)[0]` to handle duplicate string occurrences safely (such as finding resources in both text and visual chains).
    *   **Result:** All 17 frontend tests now pass successfully (0 failures).

## Final State Verification
*   **Backend Validation:** Demo environments run through real engines (`cost-processor`, `risk-engine`), yielding expected outputs perfectly aligned with the deterministic ruleset.
*   **Frontend Data Truthfulness:** Verified that no hardcoded, fake, or synthetic data is falsely portrayed as live API pulls.
*   **Test Status:** 100% Passing (17/17).
